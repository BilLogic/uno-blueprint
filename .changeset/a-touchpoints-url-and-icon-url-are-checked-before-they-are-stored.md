A touchpoint's URL and icon URL are checked before they are stored. In the Edit touchpoint dialog, a URL that is not https (a `javascript:` or `http:` link, a relative path, or text that is not a link) shows the same message a resource link would and keeps Save touchpoint disabled; a bare `figma.com/file/x` is saved as `https://figma.com/file/x`. An icon may be an https address, a path on this site (how a deployment seeds its logos), or an http address on `localhost`, `127.0.0.1` or `[::1]` (what an upload returns on the local stack); anything else keeps Save touchpoint disabled with a message, and Clear icon still clears it. The new `validateIconUrl` beside `validateResourceUrl` holds that rule. A new migration, `21000302000000`, makes `update_touchpoint` refuse the same values, so writes that never pass the dialog (the agent, the map skill, seeds) meet the rule too, with a readable error; the server does not upgrade a bare host, so those writes send the scheme. A value the row already holds is kept as it stands, so an entry stored before this stays editable and existing rows are not rewritten, and undoing a replaced seeded logo puts the path back. Undoing back to a pre-existing `http:` or other non-https URL is refused. A save that matches the row still writes nothing and returns `changed: false`.

Upgrading a deployment: port the new migration, `21000302000000`, under the deployment's own version and apply it (`supabase db push`), then bump the pin. A deployment that holds the generated recipe byte-identical takes the new copy with it.
